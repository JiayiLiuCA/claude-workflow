# 文档写作规则

读写 `docs/planning/`、功能目录下的 CLAUDE.md 或 `.claude/rules/` 时自动加载。

## 三条原则

1. **知识先放进代码，放不进的才写文档**：按下表从上往下放，越靠上越不会过期。签名、schema、路由清单、文件列表不写进文档，读代码。

   | 层 | 放什么 |
   |---|---|
   | 命名、类型、schema、enum | 数据形状、取值范围、约束 |
   | 测试，测试名描述行为 | edge case 行为 |
   | 代码旁的注释 | 故意为之、看起来像 bug 的写法的原因；会被其他功能调用的函数的契约 |
   | 域笔记 | 跨文件的行为、实测数据、否决过的方案、外部依赖改造点 |
   | ARCHITECTURE | 系统地图、涉及多个功能的规则 |

   前三层的具体写法在各层代码规范 rules 的「注释与测试」一节。
2. **只写当前状态**：决定被推翻就直接改写成新结论，不留删除线和原文。推翻的过程与理由写进当时 step 文件的「实录」和 commit 正文，历史交给 git。
3. **写到会被读到的地方**：按下表把每条信息放到将来消费它的位置，后续 session 不翻历史就能拿到。

## 信息去处

| 信息 | 去处 | 谁读 |
|---|---|---|
| 用户可见的功能现状，产品语言，不写目录 | OVERVIEW「已有功能」 | 用户 |
| 未完成 step 的目标、范围、状态 | OVERVIEW「路线图」 | 用户、plan |
| 给某个后续 step 的提示与遗留问题 | OVERVIEW 路线图中该 step 的「前置提示」 | plan |
| 尚未决定的问题 | OVERVIEW「待决」 | 用户、plan |
| 已有功能的目录、技术职责、依赖 | ARCHITECTURE「系统地图」 | 每个 session 自动加载 |
| 涉及多个功能的约束与架构规则 | ARCHITECTURE「架构规则」 | 每个 session 自动加载 |
| 单个功能内放不进代码的知识：跨文件的行为、实测数据、否决过的方案、外部依赖改造点 | 该功能的域笔记 | 读到该功能的代码时自动加载 |
| 代码约定：命名、错误处理、测试写法 | `.claude/rules/<layer>.md` | 读到对应文件时自动加载 |
| 过程：偏离、推翻了什么、路线图为什么改 | step 文件「实录」与 commit 正文 | 存档，后续阶段不读 |
| 代码能回答的 | 不写 | |

## 域笔记

域的边界由目录结构决定，bootstrap 定一次，Claude 不在每个 step 重新判断。

- **功能目录就是域**：bootstrap 选定按功能分目录、功能内部再分层，写进 ARCHITECTURE「目录结构」。新功能由 plan 在「范围内」指定新目录，close 在「系统地图」加一行。每个功能目录一份 `CLAUDE.md`。
- **放置规则**：一条知识写进包含它涉及的全部代码的最低一级目录。那是某个功能目录，就写进它的 CLAUDE.md；涉及多个功能，就写进 ARCHITECTURE。前端和后端各有功能目录时，行为写在实现它的那一侧，前端笔记只写 UI 特有的行为。
- **只放一层**：读一个文件时，从根目录到该文件沿路每一级目录的 CLAUDE.md 都会加载，层数越多读得越多。笔记只放在功能目录，压缩后仍超阈值才把子主题拆到子目录。
- **按需创建**：第一次在该功能里产生放不进代码的知识时由 execute 创建，没有这类内容不建。
- **结构从简**：功能职责已在系统地图，不重复。按主题分节，空节不写：规则与决定、跨文件的行为、实测与踩坑、外部依赖改造点。决定写成「结论。理由（Step N）」。edge case 优先写成测试，笔记只写测试表达不了的部分。
- **各阶段都可写**，hook 放行：execute 随代码更新，plan / close / hotfix 发现过期就地修正。

### 按层分目录的项目

已有项目按层分目录（`models/`、`services/`、`routers/` 各放所有功能）、或框架强制按层时，没有功能目录可放笔记。bootstrap 在 ARCHITECTURE「目录结构」注明后，域笔记改用 path-scoped rule：

- 每个功能一份 `.claude/rules/<feature>.md`，frontmatter 的 `paths` 列出该功能在各层的文件，读到其中任何一个时自动加载：

  ```markdown
  ---
  paths:
    - "backend/app/*/ocr*.py"
    - "frontend/src/pages/ocr/**"
  ---
  ```

- 内容标准、结构、放置规则与上面相同。
- hook 把 `.claude/rules/` 算作文档，execute 不能写：execute 把功能内的新知识写进 commit 正文「临场决策」段，由 close 写进这个文件，新功能由 close 新建。

## 压缩

close 发现本次碰过的域笔记超过约 150 行、或 ARCHITECTURE 超过约 200 行时，问用户是否顺带压缩。ARCHITECTURE 每个 session 都会加载，它的上限最要紧。

- 只允许三种操作：合并重复、删除已被代码或后续决定取代的条目、把历史叙述改写成当前状态。仍在生效的约束不许删，拿不准就保留。
- 保留的约束对其引用的代码位置做定点核对。
- commit 正文列「删除与合并清单」，每条一行写原因，用户审这份清单即可。
- 压缩后仍超阈值：域笔记按子目录拆分，ARCHITECTURE 把只属于单个功能的规则下沉到域笔记。

## 修改纪律

- 定点编辑，不整节重写（压缩除外），不建版本后缀文件。
- plan review 的结论（含口头调整）必须回写 step 文件的 Plan 节：execute 只认文件。
- step 文件在 close 追加实录后是存档，不再修改。
- OVERVIEW 写给用户看，用产品语言。ARCHITECTURE、域笔记、step 文件写给后续 session 的 Claude，保持技术精确。
