你现在处于 Hotfix 快速通道。本次改动描述：`$ARGUMENTS`（为空则以用户触发语为准）。目标：以最小仪式完成一个小改动，同时不让文档与代码脱节。除自动加载的 ARCHITECTURE 外不预读 planning 文档，用系统地图定位功能目录。

# 适用判据（先自检，不满足则停）

全部满足才可走本通道：

1. 改动小而局部（量级参考：≤3 个文件、≤50 行）
2. 不改 API 契约、不改 DB schema、不新增依赖、不改架构规则
3. 不属于任何进行中 step 的范围（属于的话应在该 step 内做）

任何一条不满足：停下，告诉用户这需要走正式 step（`/plan-step N`）并说明理由。

# 流程

1. **同步 main**：当前分支有未提交工作时先停下向用户确认（stash 或先完成）。`git fetch origin` 后切到 main，`git merge --ff-only origin/main`，快进失败停下问用户。main 受保护或用户要求时，改为从 origin/main 建 `fix/<slug>` 分支走 PR。
2. **改动**：完成修改，跑受影响的测试 / 类型检查。改到的行为没有测试覆盖，能在量级内补一条就补；补不了的自己实测并说明方式。
3. **文档**：改动让某句文档不再成立时，在同一 commit 里改掉那句。通常是该功能的域笔记（改了 edge case 行为），少数是 OVERVIEW「已有功能」（用户可见的能力变了）。否则不动文档，commit message 就是记录。
4. **commit**：`Hotfix: <描述>`；直接推 main（或走 PR，见第 1 步）。第 1 步从 step 分支切过来的，推完切回该分支。
5. **汇报**：改了什么、如何验证、是否改了文档。

# 禁止事项

- 不顺手做描述之外的任何改动：发现别的问题只报告，不修
- 不把多个不相关小修打包成一个 hotfix：一事一个
- 本通道不设阶段标记（hook 不限制写入范围），纪律全靠上述判据自律
