你现在处于产品定义阶段：把用户要做的产品写成 `docs/brief/PRODUCT.md`。之后 `/design-draft` 据此出设计稿，`/tech-stack` 据此选型，`/bootstrap` 据此写 ARCHITECTURE 的概述与核心概念、OVERVIEW 的定位、「不做」与路线图。本阶段只写 `docs/brief/PRODUCT.md`，不谈技术栈，不写代码。

**参数**：`$ARGUMENTS`（产品描述或已有需求文档路径；为空则从对话取）。
**续接**（resume / compact 后或新会话接着做时重新调用）：读已有的 PRODUCT.md，还空着或只有占位的节就是剩下的问题，从那里接着问；已写进「待定」的算问过，不重问。

# 第一步：读取

用户给了描述、需求文档、竞品链接或截图，先完整阅读。已有项目先读 README 与代码结构，以现状为准：已有的功能写进「功能」并标「已有」。

PRODUCT.md 已存在且不是续接：问用户是修订还是重写，不直接覆盖。

# 第二步：分轮问清

对照第三步的模板，列出不问用户就写不出来的内容，建成任务清单（TaskCreate，一题一个；会话里没有该工具就用文字列出），新冒出的问题追加。用户材料里已经写明的不再问。

**怎么问**：按依赖分轮，先问定位与用户（其他节都依赖它），再问功能与不做什么，最后问约束与页面。每轮用 AskUserQuestion 或对话，每题给推荐和备选，讲清对产品的影响。用户一时答不上的写进「待定」，不追问。每轮先一两句说上一轮定下了什么，再列本轮的问题；每拍板一项当场写进 PRODUCT.md，不等全部问完。

**问什么**：

- **功能**按「用户能做到什么」问和写，不按模块名：✗ 用户管理 ✓ 管理员能邀请同事加入、停用离职的人。一句话说得出做完后用户看到什么，才算说清；说不清的拆细，或进「待定」。bootstrap 拿这一节划 milestone 和功能目录，目录划分之后不再改，所以要在这里想稳。
- **优先级**只分两档：第一版必须有、之后再做。用户已有版本或 milestone 划分的照搬。
- **不做什么**主动问：容易被默认加上、但用户其实不要的，如多语言、移动端、多账号与权限、付费、数据导入导出。每条附一句原因。bootstrap 会把这一节抄进 OVERVIEW，之后 `/roadmap` 加需求时拿它对照。
- **核心名词**从用户的话里收：用户反复用、外人听不懂、或在本产品里有特定含义的词，每个一两句定义。bootstrap 拿它写 ARCHITECTURE「核心概念」。
- **页面**只在有界面时问：从功能推出页面清单和主要流程给用户确认，不让用户从零列。

**不问技术**：用户主动提的技术要求（必须用某语言、必须接某个现有系统）记进「约束」的「已定的技术要求」，留给 `/tech-stack`。

# 第三步：PRODUCT.md 模板

~~~markdown
# <产品名> 产品说明

> 项目启动前的输入，bootstrap 用过之后不再更新：之后的需求变化见 `docs/planning/OVERVIEW.md` 的路线图与待决。

## 定位
一两句：做什么、给谁用、解决什么问题。

## 用户与场景
- **<用户类型>**：谁，在什么情况下用，想完成什么

## 核心名词
- **<名词>**：一两句定义

## 功能

### 第一版
- **<功能名>**：用户能做到什么，一句话。涉及页面：<页面名>

### 之后
- **<功能名>**：用户能做到什么，一句话

## 不做什么
- <不做的事>：原因

## 约束
- 使用设备与环境：手机 / 电脑 / 浏览器 / 桌面应用；是否需要离线
- 数据规模与性能期望：
- 隐私、合规、预算（能否用付费服务）、时间：
- 已定的技术要求：（没有写「无」）

## 页面与流程

### 页面
| 页面 | 用途 | 主要内容 | 对应功能 |
|---|---|---|---|

### 主要流程
- **<流程名>**：<页面 A> → <页面 B> → …，每一步用户做什么

## 待定
- [ ] 问题（影响哪一节）
~~~

没有界面的产品（CLI、库、服务）删掉「页面与流程」与功能里的「涉及页面」。用户没答的节写「待定」，不留空节。

# 第四步：收尾

1. 自查：「功能」每条都说得出用户看到什么；有界面时，第一版的每个功能都有页面、每个页面都对应功能，主要流程里的页面都在页面表里；同一个名词在各节用法一致，与「核心名词」的定义相符。
2. 按 CLAUDE.md「沟通风格」的汇报顺序输出：结论一句；产品的一句话定位、第一版有几项功能（逐条一行）、不做什么；⚠️「待定」里会影响设计或选型的；👉 确认后提交，下一步有界面跑 `/design-draft`，没有界面跑 `/tech-stack`。
3. 用户确认后按 CLAUDE.md「Git 约定」commit `Product: <产品名>产品说明`，再提示下一步。
