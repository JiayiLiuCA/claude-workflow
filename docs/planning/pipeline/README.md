# 域详细参考

各子系统（域）一域一文件（如 `ocr.md`、`auth.md`、`billing.md`），由各 step 的 Close 阶段创建与维护；`PIPELINE.md` §4 只保持域索引。每个域文件固定以两张索引表开头，接着是「决议」节，其后是行为参考。

## 文件结构

~~~markdown
# <域名>

## 契约索引

| 契约 | 用途 | 实现位置 | Step |
|---|---|---|---|

（API、前端组件、模块 / 服务都记在这里，一行一条；签名细节以代码为准，不复制。**行只做定位**：后续 step 改了该契约，只在 Step 列追加号、必要时改实现位置，不在行内写「(N) 改了什么」——变更过程在该 step 的实录，行为口径在下方行为参考）

## 表索引

| 表 | 用途 | model / migration 位置 | Step |
|---|---|---|---|

（新表加一行；改字段不动本表，schema 以代码为准）

## 决议

（只有本域会引用的决议，格式同 PIPELINE §3：`- [x] 结论 + 理由（Step N 决议）`，推翻用 ~~删除线~~ 保留原文；跨域 / 路线图级 / 待决项归 §3 台账）

## 行为参考

…
~~~

## 行为参考的收录标准——只写代码读不出来的

- 行为表与 edge case 处理约定（「输入 X 时系统怎么办」的完整枚举）
- 外部依赖的集成 / 改造点清单（上游升级时按此 manual merge）
- 实测结论：性能数字、benchmark、被推翻的假设、踩坑记录
- 给后续 step 的承诺与提示（「Step X 开始前需要先…」）

代码能回答的（函数签名、schema 定义、路由清单）**不要抄进来**，索引表里的一行定位就够。
