# 域详细参考

各子系统（域）一域一文件（如 `ocr.md`、`auth.md`、`billing.md`），由各 step 的 Close 阶段创建与维护；`OVERVIEW.md` §4 只保持域索引。每个域文件固定以两张索引表开头，接着是「决议」节，其后是行为参考。

## 域怎么划分

域不在 bootstrap 时预划，由第一个落地它的 step 在 Close 阶段创建。划分依据：

1. **一个域 = 一组一起变的代码**：一个 API 模块加它的 service、package、页面。判据是「未来 step 碰它时需要整份读」。
2. **两类域**：产品功能域（用户看到的功能或流程步骤，如 `ocr.md`、`billing.md`）与横切基础设施域（被多个功能共用的东西，如共享的推理服务、数据总览页、run 生命周期）。两类都不属于的系统端点、布局壳、全局 store 进 `app-shell.md` 兜底。
3. **镜像功能不另立域**：同一逻辑的第二份（如 grading 阶段复制 modeling 的 OCR / 标注）只记与原域的差异和锁关系，行为去原域看。
4. **子系统独立成域的门槛**：有自己的 package、job 状态机或页面（如 AI 生成链路从标准 CRUD 中分出），而不只是原域的一个功能开关。
5. **拆分信号**：文件超过约 500 行且 step 每次只读其中一部分，下次 Close 时拆成两个域并在 OVERVIEW §4 各加一行；两个域总是一起改，合并。

~~~markdown

## 契约索引

| 契约 | 用途 | 实现位置 | Step |
~~~

## 行为参考的收录标准——只写代码读不出来的

- 行为表与 edge case 处理约定（「输入 X 时系统怎么办」的完整枚举）
- 外部依赖的集成 / 改造点清单（上游升级时按此 manual merge）
- 实测结论：性能数字、benchmark、被推翻的假设、踩坑记录
- 给后续 step 的承诺与提示（「Step X 开始前需要先…」）

代码能回答的（函数签名、schema 定义、路由清单）**不要抄进来**，索引表里的一行定位就够。
